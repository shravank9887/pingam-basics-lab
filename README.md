# PingAM Basics Lab

Teaching-focused Docker Compose lab: **PingAM 8.0.2** plus **three separate PingDS 8.0.2** containers (one AM profile each). No IDM, Gateway, or sample apps.

> **Not affiliated with Ping Identity.** PingAM / PingDS / Amster are licensed products you download yourself from [Backstage](https://backstage.pingidentity.com). This repo ships only lab scripts and compose files (MIT © 2026 Tech Quest).

## Architecture

| Container       | Role                                      |
|-----------------|-------------------------------------------|
| `ds-config`     | PingDS — `am-config` profile only         |
| `ds-identities` | PingDS — `am-identity-store` profile only |
| `ds-cts`        | PingDS — `am-cts` profile only            |
| `pingam`        | PingAM 8.0.2 on Tomcat                    |
| `amster`        | One-shot install + external CTS wiring    |

All three DS instances share one **deployment ID** (generated by `make secrets`) so they share a single CA. AM trusts that CA via a shared PKCS12 truststore.

**Hosts entry** (for browser access):

```
127.0.0.1 am.example.com
```

## Requirements

- Docker + Compose v2
- ~**6–8 GB RAM** free (three DS at 512m heap + AM ~1.5g)
- Licensed binaries in `artifacts/` (see `artifacts/README.md`)

## Quick start

```bash
make check          # tools + artifact checksums
make secrets        # .env with random passwords + shared DS_DEPLOYMENT_ID
make up             # build & start ds-config, ds-identities, ds-cts, pingam
make config         # Amster install (cfg+identities) + wire CTS to ds-cts
make seed           # sample users on ds-identities (password: TestUser@2024)
make smoke          # health + amadmin login + LDAP base DNs
```

AM console: <http://am.example.com:8080/am> (amadmin / see `AM_ADMIN_PASSWORD` in `.env`)

## Make targets

| Target | What it does |
|--------|----------------|
| `check` | Docker, compose, artifact SHA-256 |
| `secrets` | Create `.env` (never overwrites) |
| `up` | Build + start core stack, wait healthy |
| `config` | Amster install + external CTS; restarts AM |
| `seed` | Load `pingds/sample-users.ldif` into ds-identities |
| `smoke` | End-to-end checks (`curl --resolve`, no hosts file needed) |
| `down` | Stop containers, keep volumes |
| `reset YES=1` | Wipe containers, volumes, and `.env` |

Full clean cycle:

```bash
make reset YES=1 && make up && make config && make seed && make smoke
```

## Notes

- Compose project name: `pingam-basics`
- `.env` is never committed; secrets are random per machine
- CTS root suffix used by AM: `ou=famrecords,ou=openam-session,ou=tokens`
- `make seed` detaches the DS "Common passwords" validator so demo password `TestUser@2024` is accepted
- DS instances use `--instancePath` on a Docker volume so data survives container recreate
